# NSCLK-ESP32 —— 温湿度监控终端

ESP32 + SSD1351（128×128 RGB 彩屏）+ SHT30 + LIS3DH。
由原来的"天气摆件"改造而来：去掉联网与交互功能，改成一块纯监控终端。
它会和 RP2040 空气质量终端装进同一个外壳（无数据交互），所以视觉风格互相协调、
内容各自独立。

## 拷到板子上的文件（5 个）

| 文件 | 说明 |
|---|---|
| `main.py` | 主程序。只读 SHT30 + LIS3DH，显示委托给 `ui.py` |
| `ui.py` | **新增**。界面层，不 import 任何硬件 —— 所以能在电脑上预览 |
| `SSD1351.py` | **改过三处**（见下"驱动的三处修正"），并加了 12×12 中文绘制路径 |
| `font/utf12.bin` | **新增**。12×12 中文字集，26 字 / 624 字节 |
| `font/utf12.tab` | **新增**。码位表（升序，大端 uint16），52 字节 |

`font/` 下原有文件（font6/font8/digi/icon/boot）都不用动。
原版 `main.py` 留档为 `main.v1.bak`（这个目录不是 git 仓库，所以用 .bak 留档），不用拷。

## 相对原版的改动

**删掉的**
- WiFi：原来会连 `HUAWEI_402` 并到 `nya.ac.cn:12345` 拉天气 JSON，**用服务器数据覆盖本地读数**
- WS2812 RGB 灯（`NeoPixel(Pin(18), 1)`）
- BQ24072 充电管理（`nsclk.set_charge` / `set_charge_current`）
- 三种手势开关：倾 X 开 WiFi、倾 Y 开灯、倾 Z 息屏（含 `tri_*` 迟滞标志）
- 屏幕上的 wifi / light / charge 三个图标、电压电流文本

**改掉的**
- LIS3DH 从"手势开关"变成**姿态传感器**：开 HR 模式读满 12 位、低通滤波、`atan2` 解算
  pitch/roll，驱动屏幕上的小球水平仪
- 节奏从"阻塞式 50 次取样 × 20ms 平均（1 秒一轮）"改成非阻塞：
  LIS3DH 每 50ms、SHT30 每 1 秒滑进 8 样本窗口、屏幕独立节流 160ms
  —— 原来的阻塞平均会让水平仪一秒才动一次

**保留的**
- 开机画面（`font/boot.bin`）
- SHT30 的两个偏置修正（温度 `-3.5`、湿度 `+11`）
- `led = Pin(45)` 的板级初始化

## 驱动的三处修正

把中文字库接进来之后，`SSD1351.py` 里三个"隐含假设 h 是 8 的倍数"的地方露馅了。
三处都会**真的影响设备**，不是模拟器的问题：

1. **`bwp()` 段数 `int(h/8)`** —— h=12 时算成 1，每个 12×12 的字只画上面 8 行。
   → `int((h + 7) / 8)`
2. **`bwp()` 内层行循环画满 8 行** —— 第二段多画 4 行。
   → 在 `h` 处 `break`
3. **`bwp()` 每段发出的行数写死 8** —— 第二段只写了 4 行却发 8 行，后 4 行是缓冲区里
   上一段的残留，画面上是**"文字顶部结构重复一遍"**，并且往下溢出。→ `min(8, h - seg*8)`

另外修了两个已知问题：
- `prt()` 的 `'\x08'` 分支写的是 `char(x, y, fid, color, ' ')`，`color` 在该函数里
  未定义（参数是 `fore, back`），真用退格会 NameError
- `prt()` 的越界判断改成按"这一轮实际要画的字"的高度（中文 12 / ASCII 8）

## 三条必须遵守的布局约束（都是驱动行为，不是风格问题）

1. **底部 12 像素放不下中文**。`prt()` 的越界判断是 `y > 128 - 字高`，一旦成立就
   **清屏回到 (0,0)**。12 高的中文放在 y=120 满足 `120 > 116`，会把整屏擦掉。
   而且它是**逐字**判断的 —— 混排字符串中途遇到中文也会清屏。
2. **中文字宽 12px、ASCII(6×8) 是 6px**，排坐标不能混着按 6px 算，否则标签和数字重叠。
3. **数码管字体里没有空格**。`digi()` 的 `DIGI_MAP` 只有 `0-9 - . : C %`，落表外会取
   第 16 个字形（一个**实心方块**）。所以 `%4.1f` 这种补空格的格式化不能用，要用 `%.1f`。

## 预览与检查（跑在电脑上，与设备无关）

```powershell
$env:PYTHONIOENCODING = "utf-8"
python preview\ssd1351_sim.py      # 模拟器自检 + 能力测试图
python preview\check_sync.py       # 驱动 ↔ 模拟器 关键结构是否一致
python preview\check_layout.py     # 三版布局：状态带不溢出、标签不压数字
python preview\mock_ui.py          # 渲三版方案图
python tools\make_cjk.py           # 重新生成 font/utf12.*（字集从 ui.ZH_CHARS 读）
```

**`preview/ssd1351_sim.py` 是忠实模拟**：模拟显存 + 寻址窗口 + 流式写入，连
`__rgb_565__` 的 5-6-5 **截断**（不是四舍五入，所以"整齐"的灰在屏上并不整齐）、
`pos()` 的 `& 0x7F` 回绕、`bwp()` 的分段行为都照抄。只在主机上验证过的东西，
不能替代真机验证 —— 但反过来，一个只画几何位置的模拟器连"整屏被清"这种事都发现不了。

**`check_sync.py` 为什么重要**：驱动和模拟器是同一套算法的两份实现。这个项目里
我已经因为"只改了模拟器、漏了驱动"出过一次真机 bug（文字顶部结构重复）。
改完任一边都跑一下，全部一致才说明预览可信。

## 界面

三版布局都在 `ui.py` 里，`LAYOUT` 一行切换，函数签名一致便于对比：

| 方案 | 结构 |
|---|---|
| **A 上下分栏**（当前默认） | 上半气温+湿度，下半水平仪 |
| B 左右分栏 | 左列温湿度竖排，右列水平仪 |
| C 卡片式 | 顶部状态栏 + 两块卡片 |

共同部分：顶部 12 像素状态栏（室内 · 运行 h:mm:ss · 水平状态）、温度色阶
（≤0 蓝 / ≤16 绿 / ≤26 琥珀 / ≤31 橙 / 其余红）、小球水平仪（球朝下坡滚）、
底部 pitch/roll 数值。

改界面用字**必须同步改 `ui.ZH_CHARS`** —— 中文是子集，表外的字画不出来
（`cjk()` 找不到就什么都不画）。`tools/make_cjk.py` 从这里读字集，单一来源。
