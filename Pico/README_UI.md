# Pico —— 空气质量站的界面改版

这是 RP2040 + SSD1325（128×64，4 位灰度）空气质量站的界面重做。
原始代码从设备 `G:\` 拷来，**改版只动显示层**，读数逻辑原样保留。
按约定，**同步到设备由你自己拷**（这里不直接写 `G:\`）。

## 要拷到 G:\ 的文件（8 个）

| 文件 | 说明 |
|---|---|
| `main.py` | 主程序。读数逻辑和原版一致，绘制委托给 `ui.py`；PM 值 4 秒轮换、读数包了 `try` |
| `ui.py` | **新增**。界面层，不 import 任何硬件 —— 所以能在电脑上预览 |
| `SSD1325.py` | **改过两处**（见下「驱动的两处修正」），中文字库换成 12x12 子集 |
| `font/utf12.bin` | **新增**。12x12 中文字集，12 字 / 288 字节（原来 `utf.bin` 是 2 MB） |
| `font/utf12.tab` | **新增**。码位表（升序，大端 uint16），24 字节 |
| `icon/3001.bin` | **新增**。自己画的「叶子」，良档角标 |
| `icon/3002.bin` | **新增**。自己画的「气流」，备用角标 |
| `icon/3004.bin` | **新增**。自己画的「肺」，优档角标 |

`EnvSensor.py` / 原有 `font/`（`utf.bin` 可以留着不删，但没人再读它）/ 其余 `icon/` 都不用动。

⚠️ **`icon/` 目录**：本地已把没用的 230 个删掉了（释放 460 KB），设备上可以留着不管
（那些文件不再被引用），也可以照本地这样清一遍。

## 拷完之后

把设备复位（或软重启）即可。屏幕应该变成：

```
y=0..15   状态带（灰底）   轮换的标签 PM2.5 / PM1.0 / PM10     右侧中文等级单字
y=16..47  主区             数码管大数字 20x32                右上角 32x32 状态角标
y=48..63  CO2 行（浅灰底） CO2 580          |  甲醛 0.06
```

- PM 值每 **4 秒**换一个（`main.py` 的 `PM_ROTATE_MS`）
- CO2 固定一行，不参与轮换
- **甲醛是预留位**：传感器还没接，显示 `--`。接好之后在 `main.py` 里往 `d` 塞
  `d["hcho"] = 读数` 就行，**界面代码一行都不用改**；超过 0.08 mg/m³ 会自动反白告警
- 等级和角标按 PM2.5 分档自动变（阈值见 `ui.GRADES`）

## 为什么把界面拆成 ui.py

`ui.py` 不 import `machine` / `SSD1325`，只接收一个"看起来像 SSD1325 模块"的对象
（真机传驱动模块，电脑传 `preview/ssd1325_sim.py`）。这样界面**不用拷进设备、
不用复位等开机**就能反复调 —— 上面那些 PNG 就是直接调 `ui.py` 渲出来的，
不是另画一份示意图。

`preview/ssd1325_sim.py` 是**忠实模拟**，不是只画几何位置：它模拟面板 GRAM、
地址窗口、流式写入，连驱动里 `send()`（只发 `4*int(siz/4)` 字节）和 `fill()`
（只发 `4*int(w*h/8)` 字节）的**字节数截断**都照抄。CH559 那个项目就是因为预览工具
只画几何位置，漏掉了一个真机花屏的 bug。

## 图标：为什么要自己画

设备上原有 233 个图标是**天气桌面摆件**的素材（龙卷风、月相、雨雪），
用来表达空气质量不对路。但里面有一组正好能用：**口罩(1021) → 防毒面罩(1029) →
警告三角(9998/9999)**，是一条"防护升级"的链，用于"差"的那一端。

缺的只是"好"的一端（清新、健康）。网上 AQI 图标集授权五花八门，所以直接用
`tools/make_icons.py` 画：`3001 叶子`、`3002 气流`、`3004 肺`，
64×64 4 位灰度、2048 字节，格式和设备原有图标完全一致（id 用 3000+ 号段避开原素材）。

## 踩过的坑（都写进代码注释了）

1. **文字颜色的背景半字节必须等于所在区域的底色**。`0x0F` 的背景是 0，画在灰底上
   会抠出一圈黑框；灰带上的字要用 `0x6F`、CO2 行要用 `0x1F`。
2. **数码管大数字 20×32 要独占 32 行**，标签得让位（放状态带里），否则会压住标签。
3. **`digi()` 不要补空格**（用 `"%d"` 而不是 `"%3d"`）：大号字体的空格位是个像
   小数点的字形，补空格会多出一个孤零零的圆点。
4. **状态带右侧的等级字只能放一个字**：16×16 中文在 x=112 只剩 16px，
   两个字会越过 128 右边界，而 `prt()` 越界会**自动换行到下一行**。
5. **6×8 字模没有侧边距**，`CO2` 和数值挨着写会粘成 `CO21420`，中间要留一格。
6. **甲醛只能用两位小数**：三位（`0.065`）从 x=102 起会到 x=132，越过右边界。
7. **Pillow 的 `L` 图是 0..255**，写 `fill=15` 是近黑不是白 —— 画图标时踩过一次。

## 对原版做的一处行为改动

原版 `main.py` 直接解包：`(pm1, pm25, pm10) = Env.get_pmx(uart_pmx)`。
而 `EnvSensor.find_frame()` **找不到帧会返回 `None`**，`get_pmx/get_co2` 是直接
`return parse_frame(...)` —— 帧异常时原版会抛异常、把整个循环打断。新版包了 `try`
并检查 `None`：读不到的这一次保留上一次的有效值，屏上不跳 0、程序也不崩。

## 驱动的三处修正（这次换字体暴露出来的）

把中文字库从 16x16 换成 12x12 之后，`SSD1325.py` 里三个**隐含假设"高度是 8 的倍数"**
的地方就露馅了 —— 三处都会**真的影响设备**，不是模拟器的毛病：

1. **`prt()` 的越界判断用错了高度**
   ```python
   if (y > OLED_HEIGHT - f_h):     # f_h 是 ASCII 字库的高度，fid=2 时是 16
   ```
   字符串里混中文时，中文占的是 `UTF_H`（12）。原来一律用 `f_h`，于是 12x12 的中文
   只要 `y > 64-16 = 48` 就被误判越界、触发**"清屏回 (0,0)"** —— 整屏被清空。
   → 改成按**这一轮实际要画的那个字**的高度判断。

2. **`bin()` 的段数少算一段**
   ```python
   for seg in range(0, int(h / 8)):   # h=12 时 int(12/8) = 1
   ```
   于是每个 12x12 的字**只画了上面 8 行，后 4 行永远丢失**，字看起来是残缺的。
   → 改成 `int((h + 7) / 8)`（向上取整）。

这两个 bug 在换成 12x12 之前**都不会触发**（16 是 8 的倍数、y 也都在界内），
所以它们不是"历史遗留"，是**改尺寸带出来的**。这也是为什么 `preview/` 里的模拟器
必须**逐字照抄驱动的行为**：一个只画几何位置的模拟器根本发现不了"整屏被清"和
"少画一段"这类问题。

## 中文字体：2 MB -> 288 字节

界面里用到的中文只有 12 个字（`ui.ZH_CHARS = "优良轻中重严空气质量甲醛"`），
所以不再需要按码位索引的 2 MB 全字库：

| | 原来 | 现在 |
|---|---|---|
| 文件 | `font/utf.bin` 2,097,152 B | `font/utf12.bin` **288 B** + `utf12.tab` 24 B |
| 字形 | 16x16 | **12x12**（fusion-pixel-12px） |
| 索引 | 按码位直接算偏移 `code * 32` | **查表**（升序码位表，线性扫 12 项） |

⚠️ **加中文标签时必须同步改 `ui.ZH_CHARS`**，否则新字不在子集里、屏上是空白。
（生成脚本见 `tools/`；对照图见 `preview/out/font_compare.png` 与 `font_compare_1to1.png`。）

**为什么字集要显式声明、不扫源码**：我第一版沿用 CH559 那套"扫字符串字面量"的做法，
但这里的正则不剥注释，把 docstring 和注释里的中文全抓进去了 —— 字集从 12 字膨胀到
**285 字**、字体从 288 字节涨到 6840 字节。显式声明既准确，又顺便当成"界面文案清单"。

3. **`bin()` 每段发出的行数写死了 8**
   ```python
   bmp(x, y + seg * 8, w, 8, OLED_BUF);     # h=12 时第二段只写了 4 行，却发 8 行
   ```
   第二段的后 4 行是 `OLED_BUF` 里**上一段没被覆盖的残留**，也就是字形的第 4~7 行 ——
   真机上看到的就是**"文字顶部结构重复一遍"，并且往下溢出 4 行**。
   → 改成 `min(8, h - seg * 8)`。

   ⚠️ 这一处最值得记：**我先改了模拟器、漏了驱动**，于是预览干净、真机出问题。
   同一套算法的两份实现，只靠人眼看比对注定会漏 —— 所以补了 `preview/check_sync.py`，
   专门核对那几个出过事的结构不变量（段数、行截断、段高、pos 公式、越界判断），
   **每次改完驱动或模拟器都跑一下**：

   ```
   python preview/check_sync.py     # 5 项全 ✅ 才说明预览=真机
   ```

### 2026-10 改版：预生成 32x32 + max 池化

上面这套"自己画"的素材**本身是好的**，问题出在运行时降采样：
`badge()` 原来从 64x64 里**隔点取样**（每 2 像素取 1 个），而这些都是线条型图形，
隔点会把细笔画整根抽掉 —— 肺的细支气管、警告三角的边框全没了，屏上就是一团碎片。

现在改成**预生成 32x32**（`tools/make_icons32.py`），屏上整块 `bmp` 直贴：

```bash
python tools/make_icons32.py --preview
```

- 降采样用 **max 池化**（2x2 取最大）而不是平均：平均会把 1 像素宽的笔画
  稀释成 1/4 亮度，在 4 位灰度屏上几乎看不见；宁可粗也不可断
- 64x64 源图保留在 `tools/icon_src64/`，`icon/` 里只有 32x32（每个 512 字节）

**"严"档换成骷髅**：原来"重"和"严"共用 9998，两张图**完全相同**，屏上根本区分不出来。
骷髅由脚本程序化绘制（头骨 + 眼窝 + 鼻腔 + 牙缝），和"重"的警告三角形成明确区分。

**"轻"档从 1021 换成 3002**：1021 那张是"破损口罩"，语义含糊；3002 是气流图，
和"优（肺）/ 良（叶）/ 轻（气流）/ 中（口罩）/ 重（三角）/ 严（骷髅）"这条
递进关系更顺。
